# Release v0.207.41 — Outliner S3 sync data loss 根本修正

## ハイライト

🚨 **複数のユーザーから報告されていた「Android 等で `.out` 編集 → Mac で sync click → local 古い内容が S3 を上書きして他端末編集消失」の data loss bug を根本修正**。

## 詳細

### Root cause

log 解析で chain を完全特定:

1. webview の `Outliner.flushSync()` が編集の有無に関わらず毎回 model state を host へ送信
2. host が byte 比較で「整形差を内容違いと誤認」 (Android JSON vs Mac `JSON.stringify(..., null, 2)`)
3. `_writeFile` 発火 → mtime NOW 更新
4. `decideSyncDirection` が「local newer + size 違い」で `upload` 返却 → silent overwrite

### 修正 (案 B = content-based 検出)

`Outliner.flushSync()` を「実編集ありの時だけ host に送る」に変更:

```js
flushSync: function() {
    if (!model) return;
    var current = serializeForSave();
    if (current !== lastSentJson) syncToHostImmediate();
    // 同じなら no-op (= 編集なしで disk に無駄書き込みしない)
}
```

`lastSentJson` は webview に保持される baseline:
- `syncToHostImmediate` 末尾で更新 (= 今送った record)
- `init` / `applyExternalUpdate` / `applySyncedData` / `case 'updateData'` (fileChangeId 付き) で更新 (= disk と一致する fresh load 直後)

### 影響範囲

`flushOutlinerSync` 経由の**全経路で改善**:
- outliner toolbar の sync button
- ファイル切替 (`openFile`)
- 検索 / ジャンプ (`search` / `jumpToNode` / `jumpToMdPage`)
- Daily Notes navigation
- Tools tab 全体 S3 sync (`s3Sync` 等)
- クリーンアップ (`cleanupUnusedFilesAllNotes` 等)
- タスク archive (`archiveTasks`)

これら全部で「編集なしの操作で `.out` の mtime が無駄に更新される」事象が解消。

### 新設定: `fractal.outlinerS3SyncMode`

| 値 | 動作 |
|---|---|
| `auto` (default) | mtime newer-wins で自動判定、dialog 出さない (= シンプル) |
| `confirm` | size 違いがあれば毎回 user 確認 dialog (多端末同期で慎重派向け) |

設定例:
```jsonc
"fractal.outlinerS3SyncMode": "confirm"
```

### Custom 競合 dialog UI 改善 (`confirm` mode 時)

- Upload (blue) / Download (orange) を**左右並び固定**、色変動なし (誤クリック防止)
- 推奨マーク = 黄色 ribbon「★ おすすめ」 + 黄色 outline + glow で button 上に飛び出る
- 標準 `vscode.window.showWarningMessage` の制約 (first button が必ず blue primary、両 button 別色不可) を回避するため custom webview dialog を採用

### Reverted (workaround 撤回)

v0.207.40 で一度実装したが、より安全な案 B で根本解決したため全 revert:

- `_writeFile` semantic equal skip (parse + deep equal) → local 更新漏れ risk
- `flushSync` の `syncDebounceTimer` 検査版 → timer state が信頼できない
- `preFlushLocalInfo` 機構 → 案 B で不要

## 教訓 (`generator_failures.md` に登録済)

- webview-host data 同期は **「最後に送った内容」を記録して比較** (= 案 B)
- 外部 client (Android 等) が書く JSON は整形が違う前提で設計
- 時刻 (mtime) ベース sync 判定は他端末更新の見落としに弱い
- 自動 flush 系処理は **実 edit があるか確認してから動く**
- data loss 系 bug 修正は **二重防御 (修正 + 設定で opt-in 確認モード)** で組む
