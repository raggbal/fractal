# Release 1.3.14

## ハイライト

- **note ファイルツリーをキーボードで辿れる** — `↑↓` で行を移動しても**右のコンテンツは変わらず**、`Enter` を押したときだけ開く。仮想フォルダの行では `Enter` が展開/折りたたみ
- **「新規タブで開く」のマウス操作を cmd+shift+click に統一**（Windows / Linux: ctrl+shift+click）— note ツリーの行・outliner の 📄/📎 アイコン・md 本文のリンクの 3 面すべてで同じ操作。cmd 単独は従来の意味に戻った
- **outliner の node を右クリックして「新しいタブで開く」** — md ページ用とファイル用が別項目で並ぶ。📎 ファイルもタブで開けるようになった（note ツリーの file item も同様）
- **複数選択した node を outliner 内で D&D すると全部まとまって動く** — これまでは 1 つ目だけが移動していた

## 詳細な変更内容

### 新機能

**note ファイルツリーのキーボード操作**

- 行をクリックしてから `↑` / `↓` で 1 行ずつ移動。**移動中は右のペインが 1 度も変わらない**（ファイルの読み込みも起きない）
- `Enter` で決定 — md / `.out` はメインペイン、📎 ファイルは従来のクリックと同じ（fractal 内 viewer か OS 既定アプリ）、🔗 linkedfd はフォルダビュー、**仮想フォルダの行は展開/折りたたみ**
- `Enter` の後もフォーカスがツリーに残るので、`↓ Enter ↓ Enter` と続けて読み歩ける
- 表示範囲の外へ移ると自動でスクロールする（画面が跳ねないよう最小限の移動）
- 日本語入力（IME）の変換確定の `Enter` でファイルが開くことはない。行の名前を編集中（インライン rename）は `↑↓` がツリーに効かない
- Favorites セクションの行と、折りたたんだフォルダの中身は辿らない

**「新規タブで開く」のマウス修飾を 3 面で統一**

- **cmd+shift+click**（Windows / Linux: ctrl+shift+click）で新規タブ。対象は ①note ツリーの行（md / `.out` / 📎 ファイル / 🔗 linkedfd。**行のどこを掴んでもよい** — 小さいアイコンを狙わなくていい）②outliner の 📄 / 📎 アイコン ③md 本文のリンク
- **cmd / ctrl 単独**は面ごとの従来の意味に戻った — note ツリーでは単品トグル選択（複数選択）、outliner のアイコンと md のリンクでは通常どおり開く
- **shift 単独**クリックは範囲選択のみで、ファイルは開かない（以前は開いてしまうことがあった）

**outliner node の右クリックに「新しいタブで開く」**

- md ページを持つ node には「ページを新しいタブで開く」、📎 ファイルを持つ node には「ファイルを新しいタブで開く」。**両方持つ node では 2 項目が並ぶ**ので、どちらを開くか取り違えない
- 項目には `Cmd+Shift+Click` のショートカットが表示される
- **📎 ファイルもタブで開けるようになった**（従来はタブ化できず外部アプリのみ）。note ツリーの file item の右クリックにも「Open in new tab」が出る
- fractal 内で表示できない形式や 50MB 超のファイルは、タブを作らず OS の既定アプリで開く（メニュー項目自体は常に表示される）
- Notes 面では webview 内タブ、`.out` を単体で開いた面では VS Code のタブとして開く

**outliner 内 D&D の複数 node 一括移動**

- 複数選択したまま node のバレットを掴んで D&D すると、**選択した全部が 1 回の操作で移動**する（上に挿入 / 下に挿入 / 子にする / ツリーの余白 = 末尾 の 4 通りすべて）
- **選択時の並び順が保たれる**。`Cmd+Z` 1 回で全件まとめて元に戻る
- 親と子を同時に選んでいた場合は**最上位だけ**が動く（子は親の下に付いたまま。二重に現れない）
- 選択に含まれない node を掴んだときは、従来どおりその 1 件だけが動く
- 移動対象の中（自分自身やその子孫）へ落とそうとしたときは、1 件も動かさずに操作を無効にする

### 改善

- キーボードナビのためにツリーをフォーカス可能にしたが、**パネルに青い枠（focus ring）は出さない** — 現在位置は行のハイライトで分かる
- 仮想フォルダの行も、キーボードの現在位置になると **item と同じ色でハイライト**される

### 修正

- note ツリーで shift+click して範囲選択したときに、ファイルが開いてしまうことがあった（クリック補助経路の二重発火）
- 「Cmd+A で全選択 → ツリーの余白へ D&D」のような結果が変わらない操作で、内部的に無駄な並べ替えと undo 履歴が積まれていた
