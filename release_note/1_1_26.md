# Release 1.1.26

## ハイライト

1. **VS Code Explorer から Note tree へ D&D 取込**（shift を押しながら）— Explorer のファイルをツリーへ直接登録できるようになりました（.md は md 項目 / その他はファイル項目）。従来この経路は無反応でした。
2. **drag 中の hover 色を全面抑止** — D&D 中に item が hover 色に光って「中に drop できそう」に見える紛らわしさを解消。drop 先の可視化は専用表示（挿入線・取込ゾーン）だけになりました。
3. **D&D 可視化の表示バグ 2 件を修正** — md エディタ右端に出る全高 drop バー / outliner のアクティブ行で受理点線が途切れる問題。

## 詳細な変更内容

### 新機能

- **FR-TF-17: VS Code Explorer uri-list D&D 受理**
  - Explorer からの drag は `dataTransfer.files` が空で `application/vnd.code.uri-list` だけが載る（Finder と別物）ため、専用判定を tree の全 6 受理点（item 上 / フォルダ内 / リスト余白 × dragover+drop）に配線。
  - 取込はファイルパス（URI）を host に渡して host 側で直接読む方式。webview メモリを経由しないため **Explorer 経路に 50MB 上限はありません**（Finder からの D&D は従来どおり 50MB/file）。
  - drop 位置（項目の前後・フォルダ内・末尾）は Finder 経路と同じに効きます。
  - ※ shift 押下は VS Code の仕様（webview への drop を OS 側が横取りしないようにする操作）です。

### 改善

- **FR-TF-16: drag セッション中の hover 色抑止**
  - 外部ファイル drag・ツリー内並べ替え・outliner/md からの drag すべてで、tree の item / フォルダ行が hover 色に光らなくなりました。
  - drag をやめると（drop / パネル外へ離脱 / キャンセル）通常の hover に即復帰します。外部 drag では dragend イベントが届かないため、受け側完結のライフサイクル（dragleave / drop / window 安全網）で解除漏れを構造的に防いでいます（ADRL-0050）。

### 修正

- **md エディタの drop カーソルが右端に飛ぶ**: 本文の余白（📎 行の横など）に drag すると、エディタ端に editor 全高の縦バーが出ていました。余白ではマウス位置に出るよう修正。
- **outliner の受理点線がアクティブ行で消える**: 受理中の点線枠が、アクティブ行（水色）の背景に上塗りされて左端が欠けて見えていました。点線を全行の上に重なるオーバーレイ描画へ変更。
