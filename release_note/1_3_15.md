# Release 1.3.15

## ハイライト

- **outliner のモードが 2 つに分かれた** — 既定は **node 編集モード**（カーソルあり・打った文字が node に入る）、node を選ぶと **選択モード**（カーソルが消え、文字キーは何もしない）。選択色は**黄色（amber）に戻り**、テキスト選択の青と**色で**区別できる
- **`Cmd+A` が 2 段階になった** — 1 回目は**その node の text を全選択**、もう 1 回押すと **outliner の全 node を選択**。空の node は最初から全 node 選択
- **linkedfd 内で複数選択した D&D が全件まとまって動く** — これまでは 1 件も動かず「受け付けません」のトーストが出ていた
- **outliner ⇄ linkedfd を cmd+c / cmd+v で行き来できる** — どちらの向きも**複製**。D&D は従来どおり**移動**
- **他アプリからコピーしたリッチテキストを貼っても、無関係な `.out` ファイルが読まれることは無くなった**（セキュリティ修正）

## 詳細な変更内容

### 新機能

**outliner のモード二態（node 編集モード / 選択モード）**

- **入口**: cmd+click（Windows/Linux: ctrl+click）/ shift+click / shift+`↑↓` / `Cmd+A` の 2 回目 / 範囲選択
- **出口**: `Esc` / 修飾なしの `↑` `↓` / どこかを普通にクリック
- 選択モードでは **カーソル（caret）が消える** ので、いま文字が打てる状態かどうかが見て分かる
- 選択モードで文字キーを押しても **何も起きない**（node の text が壊れない）。以前はモードの境界が曖昧で、選択したまま打つと text が置き換わることがあった
- **選択色は amber**、テキスト範囲（`::selection`）は**青のまま**。`Cmd+A` の 1 回目と 2 回目が色で見分けられる
- note ツリー / linkedfd / mindmap の選択色は**青のまま変わらない**（outliner だけ黄色）
- **mindmap 面は対象外** — `Cmd+A` は 1 回押しで全 node 選択のまま、モードの二態化もしていない

**`Cmd+A` の 2 段階**

- 1 回目 = **その node の text を全選択**（普通のテキスト編集と同じ感覚）
- 2 回目（または既に text が全選択済み / 選択モード）= **outliner の全 node を選択**
- 空の node では 1 段目を飛ばして即 全 node 選択
- 2 段目のあと `Cmd+C` すると全 node が clipboard に入る（テキスト範囲に奪われない）

**linkedfd 内の複数選択 D&D 一括移動**

- 複数選択したファイルを掴んで drop すると **全件が一度に移動**する
- 選択に**含まれない**行を掴んだ場合は従来どおり**その 1 件だけ**（選択は変わらない）
- フォルダは D&D の対象外（選択には入るが運ばれない）。除外した件数は通知に出る
- **1 件でも移せないものが混ざっていたら drop 全体を中止**する（半分だけ動いた状態を作らない — ファイルシステムの移動は巻き戻せないため）
- 通知は**ファイルごとに出ず、最後に 1 回だけ**まとめて出る
- 201 件以上は確認ダイアログ、2000 件超は中止（取り込み側と同じ上限を共有）

**outliner ⇄ linkedfd の cmd+c / cmd+v（3 方向）**

- **linkedfd → outliner**: linkedfd で `Cmd+C` → outliner の node で `Cmd+V` すると、その node の**すぐ下の弟として**複製される。linkedfd で複数選択していれば**その並びのまま**入る
- **outliner → linkedfd**: outliner で `Cmd+C` → linkedfd で `Cmd+V`。**フォルダ行に貼るとその中**、**ファイル行に貼ると同じ階層**、**余白に貼ると root**。outliner で複数選択していた場合も全件
- **linkedfd の中で `Cmd+C` → `Cmd+V`**: その場に複製（右クリックの Duplicate と同じ）
- **D&D は移動 / clipboard は複製** — 同じ面の中でも意味が違う（意図的な非対称）
- 同名があれば既存どおり連番リネーム（`a (1).md` など）。リネームの通知は出ない
- linkedfd で行の名前を編集中の `Cmd+C` / `Cmd+V` は**テキスト操作のまま**（横取りしない）

### 改善

- linkedfd への Export（送る）でも **2000 ファイル超は理由を出して中止**するようになり、取り込み側と対称になった
- linkedfd 内の一括移動・一括複製の確認ダイアログの文言が **Import → Transfer** に変わった（同じ linkedfd の中で完結する操作で「取り込み」ではないため。**取り消せない操作**なのでダイアログの正確さが重要）

### 修正

- **他アプリでコピーしたリッチテキスト（`text/html`）を linkedfd に貼り付けたときに、無関係な `.out` ファイルが読み出される経路を塞いだ。** 貼り付け元は「あなたが実際にコピーした `.out`」か「いま開いている `.out`」と厳密に一致するかを確認してから読むようになった。**普通の `Cmd+V` の挙動は 1 つも変わらない**（Chrome からのテキスト貼り付け、md エディタへの貼り付けなど）
- linkedfd 内で**フォルダを 1 つだけ** `Cmd+C` → `Cmd+V` したとき、何のメッセージも出ず完全に無反応だったのを、理由を通知するようにした
- `.md` を複数まとめて移動したとき、**添付の一部がコピーできなかったファイルが「成功」に数えられていた**のを修正（まとめ通知に失敗として出る。元のファイルと添付はそのまま残る）
- `Esc` での選択解除が、実装上は「文字キーが来たら解除」処理の副作用で偶然効いていたのを、**明示的な `Esc` の処理**に変えた（挙動は同じだが、今後 `Esc` の動きを変えるときに意図した場所を直せる）
- mindmap のショートカット一覧（`Cmd+Shift+/`）で `Cmd+A` の説明が「2 回押すと全 node」と**実際と違う**表示になっていたのを修正

## 既知の制限

- コピー元の `.out` を閉じ、**かつ** VS Code を再起動（または別ウィンドウ）した場合のみ、outliner → linkedfd の `Cmd+V` が無反応になります（貼り付け元を検証できないため）。同じセッション内なら閉じた後でも動きます
- linkedfd は名前順に表示され兄弟の並び順を保存していないため、一括移動で「選択したときの表示順」は保たれません
- mindmap 面のモード二態化は対象外です
