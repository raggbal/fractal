-- N06 Flow Completeness -- 4/10 FAIL --

 LLM Assessment:
   The specification describes several flows but has significant gaps in error handling and edge case coverage. While 
some flows mention happy paths clearly, error scenarios are either missing entirely or handled very generically. Key 
issues include: Flow 1 (Markdown Editor edit → save) only shows the happy path with no error handling for file write 
failures or sync conflicts. Flow 2 (External Change Sync) doesn't address what happens if the external process corrupts 
the file or if the diff algorithm fails. Flow 3 (Outliner D&D file import) mentions a 50 MB guard but doesn't specify 
what error the user sees when this limit is exceeded. The document mentions "File-write failures surface via 
vscode.window.showErrorMessage" but this is too generic and doesn't specify which operations, what specific errors, or 
user recovery options. Several operations like S3 sync, translate, and drawio watching mention failure modes but don't 
describe the complete error flow from user perspective.

 Suggestions:
   1. Add specific error handling to Flow 1: what happens if TextDocument.applyEdit fails, if there's a file permission 
error, or if the debounce queue overflows
   2. Expand Flow 2 to cover edge cases: what if external process corrupts the file, if diff algorithm fails to merge 
changes, or if multiple external processes modify simultaneously
   3. Complete Flow 3 error paths: specify exact error message shown for 50MB limit, what happens if file classification
fails, or if target directory is read-only
   4. Replace generic 'File-write failures surface via vscode.window.showErrorMessage' with specific error scenarios for
each operation type
   5. Add error flows for S3 sync operations: network failures, authentication errors, bucket permission issues, and 
user recovery steps
   6. Document drawio watcher failure modes: what if drawio file is locked, corrupted, or deleted while being watched
   7. Add concurrent access scenarios: what happens if user edits while external sync is in progress, or if multiple VS 
Code instances open the same file
